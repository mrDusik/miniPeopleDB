# Guía del Proyecto (OpenSpec + Copilot)

Este proyecto sigue un flujo Spec-Driven Development.

## Reglas del agente
- Lee siempre las especificaciones activas en `openspec/changes/` antes de escribir código.
- Todas las funcionalidades deben incluir tests automatizados.
- Excepción de autenticación autorizada: `POST /api/auth/login` usa exclusivamente `anon` y la RPC `resolver_acceso_username`, nunca `service_role`. Esta RPC `SECURITY DEFINER` solo resuelve el email tras comprobar Username y contraseña, limita a cinco intentos por cuenta/minuto y no concede acceso directo a tablas privadas. Supabase Auth sigue validando el acceso y emitiendo la sesión; la ruta devuelve únicamente tokens, con errores genéricos y sin caché. Esta excepción no habilita búsquedas públicas por Username ni acceso global para otras rutas.
- Identidad pública autorizada: usar `user_profiles.username` como `perfiles_publicos.display_name` y nombre visible, nunca nombre OAuth ni email. La eliminación de cuenta propia usa JWT y la RPC sin parámetros `eliminar_cuenta_usuario`, restringida a `auth.uid()` y rol `authenticated`, sin `service_role` ni selectores de identidad; sus permisos, cascadas y rollback deben probarse con PGlite.
- La persistencia de minifiguras, gamificación e histórico diario se realiza en Supabase; las categorías de Brickset se mantienen en archivos JSON locales. Las operaciones ordinarias de usuario usan JWT y RLS, nunca `service_role`. Aparte de la excepción de autenticación anterior, el recálculo de gamificación disparado por cambios válidos de categorías y el worker backend de analítica diaria son las únicas excepciones de acceso global: solo pueden usar sus RPC allowlisted, y nunca desde rutas ordinarias ni el navegador. Los tests de API deben usar `test-support/supabase-mock.js`; los RPC administrativos y la resolución de Username deben probarse con PGlite.
